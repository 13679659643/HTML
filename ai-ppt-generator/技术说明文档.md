# AI 智能总结 PPT 生成器 — 技术说明文档

## 1. 项目概述

**AI 智能总结 PPT 生成器** 是一个纯前端 Web 应用，用户可输入文本或上传多种格式文档，通过大语言模型（LLM）完成内容总结与 PPT 页面结构设计，最终使用 PptxGenJS 在浏览器端生成并下载 `.pptx` 演示文稿。

| 属性 | 说明 |
|------|------|
| 项目类型 | 单页应用（SPA），无构建工具、无 npm 依赖 |
| 主要语言 | HTML5、CSS3、原生 JavaScript |
| 辅助脚本 | PowerShell 本地服务器（`server.ps1`） |
| 目标用户 | 需要快速将长文本/文档转为演示文稿的个人或团队 |
| 协议兼容 | 所有 LLM 调用均遵循 **OpenAI Chat Completions** 格式 |

---

## 2. 项目结构

```
ai-ppt-generator/
├── index.html          # 主应用（UI + 样式 + 全部业务逻辑，约 1200 行）
├── server.ps1          # 本地 HTTP 服务 + CORS 反向代理
└── 技术说明文档.md      # 本文档
```

项目刻意保持极简结构：所有前端逻辑集中在 `index.html` 内，便于部署与二次开发。

## 4. 核心业务流程

应用采用**三按钮独立流水线**设计，各步骤可单独执行，也可串联使用：

```
输入内容（文本 / 文件）
        │
        ├─► [AI 总结] ──► 模型 A ──► Markdown 总结 ──► 预览区
        │
        └─► [生成 PPT 结构] ──► 模型 B ──► JSON 幻灯片数组 ──► 预览区
                    │                              │
                    │（优先使用已有总结，否则用原始文本）│
                    │                              ▼
                    └──────────────────────► [下载 PPT] ──► .pptx 文件
```

### 4.1 AI 总结（模型 A）

- **入口函数**：`handleSummarize()`
- **输入**：文本框内容 + 已上传文件提取的文本（合并后截取前 30000 字符）
- **输出**：Markdown 格式总结，存入全局变量 `summaryMarkdown`，并用 `marked` 渲染到预览区
- **System Prompt 结构**：核心摘要 → 关键要点（5 条）→ 详细分析（3 个主题）→ 结论与建议

### 4.2 生成 PPT 结构（模型 B）

- **入口函数**：`handleGeneratePPT()`
- **输入优先级**：`summaryMarkdown`（若存在）> 原始合并文本
- **可选参数**：`pptPrompt` 输入框中的自定义风格/受众指令
- **输出**：JSON 数组，存入 `parsedSlides`
- **容错**：若 AI 返回无法解析的 JSON，自动调用 `buildFallbackStructure()` 从 Markdown 标题/列表本地解析

### 4.3 下载 PPT

- **入口函数**：`handleDownload()` → `generatePPT(slides)`
- **依赖**：`parsedSlides` 非空（需先执行「生成 PPT 结构」）
- **渲染库**：PptxGenJS，16:9 宽屏布局，默认「商务蓝」主题

## 6. 文件解析模块

| 格式 | 扩展名 | 解析函数 | 实现方式 |
|------|--------|----------|----------|
| Excel | `.xlsx` `.xls` `.csv` | `parseExcel()` | XLSX.read → 各工作表转 CSV 文本 |
| Word | `.docx` | `parseWord()` | mammoth.extractRawText |
| PowerPoint | `.pptx` | `parsePPTX()` | JSZip 解压 → 正则匹配 `<a:t>` 文本节点 |
| 纯文本 | `.txt` | `file.text()` | 原生 File API |
| 旧格式 | `.doc` `.ppt` | — | 提示用户转换为新格式 |

上传文件存入 `uploadedFiles` 数组，文本合并至 `extractedText`，支持多文件与单独移除（`removeFile()`）。

## 7. 双模型配置

应用支持为两个独立任务分别选择 LLM 服务商与 API Key：

| 插槽 | DOM ID 前缀 | 职责 | 默认服务商 |
|------|-------------|------|------------|
| 模型 A | `providerSelectA` / `apiKeyA` | 长文本深度总结 | 通义千问 Qwen |
| 模型 B | `providerSelectB` / `apiKeyB` | PPT 页面结构 JSON 生成 | 通义千问 Qwen |

### 7.1 内置服务商（`PROVIDERS` 配置表）

| Key | 名称 | 默认 Endpoint | 默认 Model |
|-----|------|---------------|------------|
| `qwen` | 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions` | `qwen-max` |
| `kimi` | Kimi (Moonshot) | `https://api.moonshot.cn/v1/chat/completions` | `moonshot-v1-auto` |
| `yuanbao` | 腾讯元宝 (混元) | `https://api.hunyuan.cloud.tencent.com/v1/chat/completions` | `hunyuan-turbos-latest` |
| `doubao` | 豆包 (火山引擎) | `https://ark.cn-beijing.volces.com/api/v3/chat/completions` | `doubao-pro-32k` |
| `deepseek` | DeepSeek | `https://api.deepseek.com/chat/completions` | `deepseek-chat` |
| `zhipu` | 智谱清言 (GLM) | `https://open.bigmodel.cn/api/paas/v4/chat/completions` | `glm-4-plus` |
| `36kaippt` | 36KaiPPT | `https://api.36kaippt.com/v1/chat/completions` | `36kaippt-v1`（占位，需按官方文档修改） |
| `custom` | 自定义 | 用户输入 | 用户输入 |

选择「自定义」时显示 Endpoint 与 Model 输入框，适用于 OpenAI、Azure OpenAI、Ollama、vLLM 等兼容服务。

### 7.2 统一 API 调用（`callLLMAPI`）

**请求格式：**

```http
POST {endpoint 或代理 URL}
Authorization: Bearer {API_KEY}
Content-Type: application/json

{
  "model": "模型名",
  "messages": [
    { "role": "system", "content": "系统提示词" },
    { "role": "user", "content": "用户内容" }
  ],
  "temperature": 0.3,
  "max_tokens": 8192
}
```

**响应解析：**

```javascript
data.choices[0].message.content
```

**代理候选优先级：**

1. `localhost` / `127.0.0.1` → `/api-proxy?url={encodeURIComponent(endpoint)}`
2. 用户填写的 CORS 代理前缀 + endpoint
3. 公共代理：`cors.eu.org`、`corsproxy.io`
4. 直连 endpoint

每个候选最多重试 3 次（网络错误时递增等待），全部失败则抛出详细错误信息。

## 8. PPT 数据结构

模型 B 应返回如下 JSON 数组（应用用正则 `\[[\s\S]*\]` 提取）：

```json
[
  {
    "type": "cover",
    "title": "主标题",
    "subtitle": "副标题/日期"
  },
  {
    "type": "content",
    "title": "页面标题",
    "bullets": ["要点1", "要点2", "要点3"],
    "note": "可选补充说明"
  },
  {
    "type": "ending",
    "title": "感谢观看",
    "subtitle": "副标题"
  }
]
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `type` | string | `cover`（封面）/ `content`（内容页）/ `ending`（结尾页） |
| `title` | string | 页面主标题 |
| `subtitle` | string | 封面/结尾页副标题 |
| `bullets` | string[] | 内容页要点列表（每页建议 ≤ 5 条） |
| `note` | string | 内容页底部补充说明（可选） |

**生成约束（写入 System Prompt）：**

- 总页数 5–8 页（含封面与感谢页）
- 每页要点不超过 5 个，每条 15–40 字
- 标题不超过 12 字

## 9. PPT 视觉主题（`STYLE_THEMES`）

代码中预置三种配色方案，当前下载功能**固定使用 `business`（商务蓝）**：

| Key | 名称 | 特点 |
|-----|------|------|
| `business` | 商务蓝 | 深蓝底 + 蓝色强调，正式场合 |
| `tech` | 科技紫 | 深紫底 + 紫色强调 |
| `minimal` | 简约白 | 白底黑字，适合打印 |

每种主题包含颜色令牌：`primary`、`accent`、`dark`、`text`、`muted`、`white`、`bg1`、`bg2`、`accentBar` 等（6 位十六进制，不含 `#`，符合 PptxGenJS 要求）。

**幻灯片布局说明：**

- 布局：`LAYOUT_WIDE`（16:9）
- 字体：`Microsoft YaHei`
- 封面/结尾：顶部装饰条 + 左侧竖条 + 底部色带
- 内容页：标题栏 + 编号 + 项目符号列表 + 可选 note 斜体脚注

导出文件名格式：`AI_PPT_{主题名}_{日期}.pptx`

## 10. 本地服务器（server.ps1）

### 10.1 功能

| 路由 | 方法 | 说明 |
|------|------|------|
| `/` | GET | 返回 `index.html` |
| `/{path}` | GET | 静态文件服务（html/js/css/json/图片等） |
| `/api-proxy?url={target}` | POST | CORS 反向代理，转发 Body 与 Authorization 头 |
| `*` | OPTIONS | CORS 预检响应（204） |

### 10.2 启动方式

```powershell
# 在 ai-ppt-generator 目录下右键「使用 PowerShell 运行」
# 或在终端执行：
powershell -ExecutionPolicy Bypass -File server.ps1
```

默认监听端口：**3000**（注释中写有 3001，实际代码为 `$port = 3000`）

访问地址：`http://localhost:3000`

### 10.3 代理实现要点

- 使用 `System.Net.HttpListener` 实现轻量 HTTP 服务
- 通过查询参数 `url` 传递目标 API 地址，避免路径中双斜杠问题
- 兼容旧版路径格式 `/api-proxy/https://...`（自动修复 `https:/` → `https://`）
- 响应统一添加 `Access-Control-Allow-Origin: *`
- 4xx/5xx 错误通过 `WebException.Response` 正确回传

## 14. 部署与使用场景

### 场景 A：本地服务器（推荐）

1. 运行 `server.ps1`
2. 浏览器访问 `http://localhost:3000`
3. API 请求自动走 `/api-proxy`，无需配置 CORS

### 场景 B：直接打开 HTML（file://）

1. 双击 `index.html`
2. 自动尝试公共 CORS 代理
3. 稳定性较差，可能受代理服务限制

### 场景 C：部署到 Web 服务器

1. 将 `index.html` 上传至任意静态托管（Nginx、GitHub Pages 等）
2. 需自行配置 CORS 代理或后端转发，否则多数 LLM API 会被浏览器拦截
3. 建议同时部署等效的 `/api-proxy` 反向代理接口

## 15. 安全与隐私

| 风险点 | 说明 | 建议 |
|--------|------|------|
| API Key 暴露 | Key 存于 localStorage，且代码中含默认测试 Key | 生产环境删除 `DEFAULT_API_KEY`，仅由用户自行输入 |
| 前端直连 API | Key 随请求从浏览器发出，可被网络嗅探 | 正式使用应通过后端代理隐藏 Key |
| 公共 CORS 代理 | 请求经第三方转发，存在数据泄露风险 | 优先使用 `server.ps1` 或自建代理 |
| 文件本地解析 | 文档内容不自动上传第三方（除 LLM API 调用外） | 敏感文档注意选择可信模型服务商 |

## 16. 错误处理机制

`callLLMAPI` 对常见 HTTP 状态码提供中文修复建议：

| 状态码 | 提示方向 |
|--------|----------|
| 400 | model 名称或 messages 格式错误 |
| 401 | API Key 无效或过期 |
| 403 | 权限不足或余额不足 |
| 404 | endpoint 或 model 不存在 |
| 429 | 频率限制，稍后重试 |
| 5xx | 服务端错误 |

网络层失败时汇总所有已尝试代理方式，并建议运行 `server.ps1` 或安装 CORS 插件。

## 17. 已知限制

1. **旧版 Office 格式**：`.doc`、`.ppt` 不支持解析，仅提示转换
2. **PPTX 文本提取**：仅读取 XML 文本节点，不保留版式/图片
3. **输入长度**：总结阶段截取前 30000 字符
4. **主题选择**：UI 已移除风格卡片，下载固定商务蓝（`tech`/`minimal` 仅代码预留）
5. **36KaiPPT**：Endpoint 与 Model 为占位配置，需按官方文档更新
6. **server.ps1 端口**：注释写 3001，实际为 3000，以代码为准
7. **离线不可用**：依赖 CDN 与在线 LLM API，无离线模式

## 18. 扩展开发指南

### 18.1 新增 LLM 服务商

在 `PROVIDERS` 对象中添加条目，并在两个 `<select>` 中增加 `<option>`：

```javascript
newprovider: {
  name: '显示名称',
  endpoint: 'https://api.example.com/v1/chat/completions',
  model: 'model-id',
  placeholder: 'API Key 输入提示',
  info: '底部说明文字'
}
```

### 18.2 切换 PPT 下载主题

修改 `generatePPT()` 中的：

```javascript
const theme = STYLE_THEMES.business; // 改为 tech 或 minimal
```

或恢复 UI 风格选择器并绑定 `selectedStyle` 变量。

### 18.3 调整总结/PPT Prompt

- 总结格式：编辑 `handleSummarize()` 内 `summarySystem` 字符串
- PPT 结构规则：编辑 `handleGeneratePPT()` 内 `pptSystem` 字符串

### 18.4 增加文件格式支持

在 `handleFiles()` 的 `ext` 分支中添加解析逻辑，并实现对应 `parseXxx()` 函数。
